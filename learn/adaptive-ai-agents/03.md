## 中心思想

这一集讲**第一层适应——行为层**：把智能体留下的轨迹（trace）**炼成可复用的技能**，这样明天的智能体就不会重犯昨天的错。

具体做法叫**技能归纳（skill induction）**：归纳引擎用 LLM 读一批原始轨迹，起草一份简短的流程，写成 `skill.md` 文件；**经人批准后**，这份技能进入 skill box（技能箱），从此在每一个匹配的任务上被自动调用。因为批准等于把一份提案变成行为，坏技能一旦溜进去就会天天重犯、伤害不断累积，所以**人必须留在环上**。

## 核心要点

- **这一课要做的事**：把智能体的轨迹（过去的对话、工具调用、报错和修复）变成可复用的技能，这样明天的智能体就不会重犯昨天的错。
- **什么叫技能归纳（skill induction）**：拿原始轨迹——也就是智能体试过什么、在哪儿失败、最后什么管用的日志。**归纳引擎（induction engine）** 用 LLM 来审这些轨迹，起草一份简短的流程，形式是一个 `skill.md` 文件。然后**经人批准**，这份技能进入 **skill box**——一个受管的技能集合，供智能体取用。在这个过程里，我们把智能体的**一次运行**变成了**别的智能体以后也能用**的技能。
- **怎么让技能持续变好（这是个循环）**：
  1. 从 skill box 里已批准的技能出发。
  2. 智能体用这些技能去完成新任务，于是**更多的轨迹堆积起来**。
  3. **在智能体主管道之外**，跑归纳引擎去读这些轨迹，提出「一份增强版技能 + 每一处改动的证据」。
  4. 人工审核：**批准**就升进 skill box 供智能体使用；**驳回**就给出理由，让归纳引擎下次能生成更好的增强提案。
- **为什么必须有人在环上**：想想批准这个动作实际做了什么——**它把一份提案变成了行为**。技能一旦被批准，从此在每一个匹配的任务上，智能体都会调用它。这是它的力量，也是它的风险。
  - **风险一**：如果一个坏技能溜了过去，智能体就会**每次都重犯这个错，伤害不断累积**。
  - **风险二**：轨迹是智能体从世界里收集来的数据。错误、甚至是被**故意植入**的指令，都可能被当成技能提出来。人工审核就是那道闸，挡住一条"毒轨迹"变成行为。
  - **附带好处**：因为是人点下批准或驳回并给出理由，所以 **skill box 里的每一份技能都有一个负责人**，而每一次驳回都在教归纳引擎下次该修什么。
- **演示里用到的两个开源包**：**Oracle Agent Memory**（用来存轨迹）和 **LangGraph + Oracle DB**（用来跑技能归纳循环）。
- **演示用的五份技能**：brainstorming（头脑风暴）、requesting code review（请求代码评审）、run the tests（跑测试）、systematic debugging（系统性调试）、writing plans（写计划）。每份技能展示它的名字、主题、以及具体的流程。
- **轨迹被拆成这几类内容**：对话轮次（conversation turns）、工具调用（tool calls）、技能使用（skill uses）、流程步骤（workflow steps）、偏好（preferences）、以及报错和修复（errors and fixes）。
- **归纳引擎的契约（contract）**：也就是给 LLM 的指令。这份契约把**同一个主题下的所有片段**收拢起来，蒸馏成可复用的流程和经验教训，输出步骤、工具、报错、修复、以及任何需要的来源信息（provenance）。
- **演示结果**：引擎从轨迹里发现了一个**反复出现的失败**和对应的修法，据此提出了一份新的增强版技能，包含智能体可以照着做的**四个步骤**。人审通过后，`run the test` 的技能从 v1 升到 v2，设为 active。**用同样的问题再跑一遍智能体**，它加载了 v2，用上了改进后的流程，**整个测试集全部通过**。

> 首先，我们看看技能归纳是什么意思。我们拿原始轨迹，也就是智能体试过什么、在哪儿失败、最后什么管用的日志。归纳引擎用 LLM 来审这些轨迹，起草一份简短的流程，形式是一个 `skill.md` 文件。然后经人批准，这份技能可以进入我们的 skill box——一个受管的技能集合，供智能体取用。在这个技能归纳的过程里，我们把智能体的这次运行，变成了别的智能体以后也能用的技能。
> First, let's see what skill induction means. We take the raw traces, which is the log of what the agent tried, where it failed, and what finally worked. The induction engine uses an LLM to review those traces, and drafts a short procedure in the form of a skill.md file. Then, with a human approval, this skill can go into our skill box, which is a managed collection of skills available to the agent. Within this skill induction process, we are turning the agent's run into a skill other agents can also use in the future.

### 怎么让技能持续变好：从 skill box 里已批准的技能出发，智能体用它们完成新任务、于是堆出更多轨迹；然后在智能体主管道之外跑归纳引擎，提出一份增强版技能和每一处改动的证据；人工审核要么批准（升进 skill box 供智能体使用），要么驳回（给出理由，让引擎下次生成更好的增强提案）

> 那我们怎么让这些技能持续改进，让智能体一天比一天强呢？我们从智能体 skill box 里已批准的技能开始。当智能体用这些技能去完成新任务时，随着它和环境互动，更多的轨迹会开始堆积起来。现在，在智能体主管道之外，我们跑归纳引擎去读这些轨迹，提出一份增强版的技能，以及每一处改动的证据。下一步，人工审核者可以审这份增强技能提案，要么批准它、把它升进 skill box 供智能体使用，要么驳回并给归纳引擎一个理由，让它能生成更好的增强提案。
> So how do we continually improve these skills so the agent gets better every day? Let's start with our approved skills in the agent's skill box. As the agent uses these skills to accomplish new tasks, more traces will start to pile up as the agent interacts with its environment. Now, outside of the main agent's working path, we then run the skill induction engine to take those traces and propose an enhanced version of the skill, plus evidence for each proposal. In the next step, the human reviewer can review the enhanced skill proposal, and either approve this skill, promoting it to the skill box to be used by the agent, or decline, giving the skill induction engine a reason so that it can generate a better proposed enhancement.

### 为什么必须有人在环上：批准这个动作实际是把一份提案变成行为——技能一旦被批准，从此每个匹配的任务都会调用它，这是它的力量也是它的风险；坏技能一旦溜过去，智能体每次都重犯、伤害不断累积；另一个风险是轨迹属于智能体从世界里收集来的数据，错误甚至被故意植入的指令都可能被提成技能，人工审核就是挡住毒轨迹变成行为的那道闸；还因为人点批准或驳回时会给出理由，skill box 里每个技能都有负责人，每次驳回都在教引擎下次该修什么

> 那为什么我们需要有人在环上（human in the loop）呢？想想批准这个动作实际做了什么。它把一份提案变成了行为。技能一旦被批准，从此在每一个匹配的任务上，智能体都会调用它。这就是它的力量，也是它的风险。如果一份坏技能溜了过去，智能体就会每次都重犯这个错，伤害不断累积。另一个风险是，轨迹是智能体从世界里收集来的数据。不正确、甚至是被人故意植入的指令，都可能被当成技能提出来。人工审核就是那道闸，挡住一条"毒轨迹"变成行为。而且因为是人点下批准或驳回并给出理由，所以 skill box 里的每一份技能都有一个负责人，每一次驳回也都在教归纳引擎下次该修什么。
> So why do we need a human in the loop? Think about what approval actually does. It turns a proposal into behaviour. Once a skill is approved, the agent retrieves it on every matching task from now on. That's the power and the risk. If a bad skill slips through, the agent repeats the mistake every time and the damage compounds. Another risk is that traces are the data the agent collected from the world. Incorrect or even deliberately planted instructions could get proposed as a skill. The human review is the gate that stops a poison trace from becoming behaviour, and because a human clicks approve or reject with a reason, every skill in the skill box has an owner, and every rejection teaches the engine what to fix next time.
