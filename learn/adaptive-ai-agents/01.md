## 中心思想

这门课解决智能体的一个致命短板：**每次会话都从零开始**。智能体会写代码、会用工具、能完成复杂任务，可它不记得昨天已经找到过的解法，于是同一个问题被反复重新解决一遍。

解法是给智能体装上"记住经验"的机制——**不要把每次交互当成一次孤立的会话**，而是让它把有用的信息留存下来，明天干得更好。课程具体带大家搭一个自适应编码智能体，它有**两层适应机制**：第一层**行为适应**，让智能体的技能随着运行越来越强；第二层**知识适应**，建一张代码知识图谱，让它记住代码里的主要关系。

## 核心要点

- **课程来源**：DeepLearning.AI 与 Oracle 联合出品，讲师是 Nacho Martinez 和 Casius Lee。
- **要解决的短板**：智能体会写代码、会用工具、能完成很多复杂任务，但它可能不得不**反复解决同一个问题**——因为它不记得昨天已经找到的解法，于是又把它重新发现一遍。
- **全课的关键思想**：不要把每次交互当成一次孤立的会话（isolated session）。我们可以给智能体一些机制，让它**记住有用的信息**，并用这些信息在明天表现得更好。
- **你会搭出来的东西**：一个自适应编码智能体，带两层适应机制。
  - 第一层，**行为适应**：随着运行不断改进智能体的技能。
  - 第二层，**知识适应**：建一张知识图谱，让智能体跟踪代码里的主要关系。
- **轨迹（trace）**：每一次智能体运行都会留下轨迹，也就是它的对话、工具调用、决策、报错和修复。
- **技能归纳管道（skill induction pipeline）**：把轨迹里反复出现的经验变成可复用的技能。这样智能体不用每次重新发现同一套工作流程，还能避开已经犯过的错，**一天比一天表现更好**。
- **知识适应要回答的问题**：为什么在大代码库里，**检索和构建正确的上下文往往才是真正的瓶颈**；为什么关键词搜索和正则表达式匹配经常漏掉那些真正重要的文件。
- **代码知识图谱**：从零搭起，用 imports、function calls、以及 Git 历史里的 co-edits 把文件连起来，用这种结构去检索，**让检索方式反映代码库实际是怎么组织的**。
- **对比实验**：把基于图的检索和传统的文本搜索放在一起比，看结构化记忆怎么帮编码智能体干得更快、决策更好。
- **致谢名单**：Oracle 的 Richmond Alake 和 Wojtek Pluta；DeepLearning.AI 的 Esmaeil Gagari 和 Brendan Brown 也参与了这门课的制作。
- **下一课预告**：建立自适应智能体的心智模型——它到底是什么，以及为什么"遗忘"会增加成本、让智能体变得没那么有效；还会讲不同学习方式之间的权衡。
