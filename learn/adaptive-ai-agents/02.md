## 中心思想

这一集是全课的**概念地图**：先把"自适应智能体"这个词定义清楚，再讲明白**遗忘到底贵在哪**，最后给出该从哪儿下手的判断顺序。

核心是一个**从便宜到贵的梯子**。你要先问自己一句：**更好的上下文和指令，能不能提升智能体的表现？** 能的话就走**token space（词元空间）**的两条路——让技能自己适应（第 3 课），或者用知识图谱搭自适应记忆（第 4-5 课）。这两条都走尽了还是不行，才轮到最贵的**weight space（权重空间）**：动模型本身（第 6 课）。

还有一个贯穿全课的关键区分：**智能体 = 模型 + 外壳（harness）**。模型只是推理的那股劲；真正组装上下文、跑工具、写记忆的是外壳。

## 核心要点

- **今天的智能体会写代码、会用工具、能解复杂任务，但它经常重复犯同样的错**，因为它不把经验带到下一次。
- **这一课要建立三样东西**：自适应 AI 智能体的心智模型、为什么遗忘很贵、智能体可以从哪些地方改进。
- **周一 / 周二 / 周三的例子**：
  - **周一**：你让编码智能体跑 Python 测试，但 Python 解释器找不到项目里的某个模块。智能体去排查，发现了正确的项目命令，把测试跑通了。
  - **周二**：你开了一个全新的对话，让它做一件很类似的事。因为没有周一的记忆，它**又跑了错命令，又撞上同一个报错**，再花时间和 token 去重新发现同一个修复方法。
  - **周三应该是不同的样子**：我们希望它记得周一验证过的命令，直接从那开始，跳过周二浪费掉的时间和 token。
- **遗忘的代价**：没有记忆和学习，每一次重复的迭代，都是模型推出错误答案、多烧 token 的又一次机会。反过来，如果智能体从第一天的经验里学到了，第二天就会好得多，而且**几乎不花钱**。
- **什么是智能体**：一个能从环境里接收信息、用 LLM 推理下一步该做什么、并用工具作用于环境的系统。如果它**有记忆**，它还能把过去有用的经验留住。**没有记忆**，它可能完成今天的任务，但不会把学到的东西留到明天。
- **智能体循环（agent loop）是怎么转的**（用测试失败的例子）：
  1. 从用户请求开始——让智能体跑 Python 测试。
  2. 推理时，模型判断它需要检查项目仓库，于是向外壳（harness）申请一个工具。
  3. 外壳执行这个工具去检查项目，并把结果返回。
  4. 模型接着选择跑一条单独的测试命令，再申请一个工具、再跑一次，又返回一个错误。
  5. 模型的回复和工具结果（包括那个报错）都成为下一轮迭代的上下文历史。
  6. 如此重复，直到测试通过，或者智能体停下来。
- **什么是外壳（harness）**：LLM 是智能体的**原始推理能力**，外壳是它周围的**软件脚手架**。外壳负责组装模型看到的上下文、给模型访问和执行工具的能力、把结果记录进记忆、并在智能体循环里再次调用模型。**模型加外壳，合起来才是一个能干活的智能体。**
- **记忆的四个类别**：
  - **工作记忆（working memory）**：此刻正在使用的消息和工具结果。
  - **情景记忆（episodic memory）**：以前那些智能体运行里发生过的任何事。
  - **语义记忆（semantic memory）**：项目相关的事实和知识。
  - **程序性记忆（procedural memory）**：智能体学到的流程步骤。
- **下一课聚焦程序性记忆**：把经验变成可复用的技能。DeepLearning.AI 上一门关于"构建有记忆感知的智能体"的课深入讲过这部分，想了解更多可以去看看。
- **长期记忆怎么建**：从**轨迹（trace）**开始。轨迹就是一次智能体交互里**每一个事件的完整记录**。一个轨迹里包含：智能体干活时查看过的项目文件、为解决问题采取的动作、这些动作的结果、以及智能体做的修正。这些轨迹就是学习的**原材料**。
- **该先在哪里下手**：你要问的主要问题是——**更好的上下文和指令，能不能提升智能体的表现？** 如果能，就用我们归为**token space adaptation（词元空间适应）**的两个主要手段：先建一个增强循环，让智能体的技能适应并变得更好；再用知识图谱搭一套自适应记忆。
- **什么时候才轮到模型**：如果这些手段都被用尽了，再没有什么能让智能体变得更好，那才去看模型本身在**weight space（权重空间）**里还有哪些可以增强的地方。这是最后一课的重点。

> 到了周二，你开了一个全新的对话，让它做一件很类似的任务。因为没有周一的记忆，它又跑了错命令，又撞上同一个报错，再花时间和 token 去重新发现同一个修复方法。

> So how do we want Wednesday to be different? Well, we want it to remember the proven command from Monday and start there, bypassing the wasted time and tokens spent on Tuesday. That's the gap we're trying to close in this course.

### 遗忘的代价：周二那个智能体把同一轮排查又做了一遍，多花时间和 token 去修同一个问题；没有记忆和学习，每一次重复的迭代都是模型推出错误答案、多烧 token 的又一次机会；反过来，如果智能体从第一天的经验里学到了，第二天就会好得多，而且几乎不花钱

> 我们也来看看这种遗忘的代价。我们那个智能体周二又把同一轮排查做了一遍，多花时间和 token 去修同一个问题。没有记忆和学习，每一次重复的迭代都是模型推出错误答案、多花 token 的又一次机会。反过来，如果智能体从第一天的经验里学到了，第二天就会好得多，而且几乎不花钱。
> Let's also take a look at the cost of that forgetting. Our agent on Tuesday repeats the same investigation and spends more time and tokens on fixing that issue again. Without memory and learning, every repeat iteration is another chance for the model to derive the wrong answer and spend more tokens. In contrast, if the agent learns from day one's experience, then day two will be a lot better and almost free.

### 先定义智能体：智能体是一个能从环境接收信息、用 LLM 推理下一步该做什么、并用工具作用于环境的系统；如果它有记忆，它还能把过去有用的经验留住——没有记忆，它可能完成今天的任务，但不会把学到的东西留到明天

> 在学怎么改进智能体的学习方式之前，我们先简单把"智能体"这个词说清楚。智能体可以定义成一个这样的系统：它能从环境里接收信息，用 LLM 推理下一步该做什么，并用工具作用于环境。如果智能体有记忆，它还能把过去有用的经验留住。没有记忆，智能体可能完成今天的任务，但不会把学到的东西留到明天。
> Before we learn about improving how agents can learn, let's briefly get clear on what we mean by an agent. An agent can be defined as a system that can take in information from its environment, reason about what to do next using an LLM, and use tools to act on its environment. If an agent has memory, it can also hold onto useful experience from the past. Without memory, the agent may complete today's task but won't retain what it's learned tomorrow.

### 智能体循环怎么转：从用户请求开始，模型判断需要检查项目仓库、向外壳申请工具，外壳跑工具并把结果返回，模型再选择跑一条单独的测试命令、又申请一个工具、又返回一个错误；模型的回复和工具结果（包括那个报错）都成为下一轮迭代的上下文历史，如此重复直到测试通过或者智能体停下来

> 我们用编码智能体测试失败这个例子，看看智能体循环是怎么转起来的。循环从一条用户请求开始，我们让智能体跑 Python 测试。推理期间，模型判断它需要检查项目仓库，于是向智能体外壳申请一个工具。外壳执行这个工具去检查项目，并把结果返回。模型接着选择跑一条单独的测试命令，再申请一个工具、再跑一次，又返回一个错误。模型的回复和工具结果（包括那个报错）随后都成为下一轮迭代的上下文历史的一部分。这个过程一直重复，直到测试通过，或者智能体停下来。
> Let's use our coding agent's test failure example to see the agent loop in action. We start the loop with a user request, asking the agent to run our Python tests. During inference, the model decides it needs to inspect the project repository, so it requests a tool from the agent harness. The harness runs the tool to inspect the project and returns the result. The model then chooses to run a separate test command, requests another tool, runs it, and another error is returned. The model's responses and tool results, including the error, then become part of the context history for the next iteration. This repeats until the tests pass or the agent stops.

### 什么是外壳（harness）：LLM 是智能体的原始推理能力，外壳是它周围的软件脚手架——它组装模型看到的上下文、给模型访问和执行工具的能力、把结果记录进记忆、并在智能体循环里再次调用模型；模型和外壳合起来，才是一个能干活的智能体

> 既然刚提到了"外壳（harness）"这个词，我们也把它拆开讲讲。LLM 是你智能体的原始推理能力。外壳是它周围的软件脚手架。它组装模型看到的上下文，给模型访问和执行工具的能力，把结果记录进记忆，并在智能体循环里再次调用模型。把模型和外壳放在一起，你就有了一个能干活的智能体。
> Since we just used the word harness, let's also unpack that. The LLM is the raw reasoning power for your agent. The harness is the software scaffolding around it. It assembles the context the model sees, gives the model access and ability to run tools, records the results to memory, and calls the model again within the agent loop. Put the model and the harness together, and you have a working agent.

### 记忆分四类：此刻正在用的消息和工具结果是工作记忆，以前那些运行里发生过的事是情景记忆，项目相关的事实和知识是语义记忆，智能体学到的流程步骤是程序性记忆——下一课聚焦最后这一类，把经验变成可复用的技能；DeepLearning.AI 上一门关于构建有记忆感知的智能体的课深入讲过这部分

> 我们也来看看智能体可以有哪些不同类型的记忆。我们可以把这些记忆分成四个类别。第一，此刻正在使用的消息和工具结果，是工作记忆。另外，以前那些智能体运行里发生过的任何事，成为情景记忆。项目相关的事实和知识，成为语义记忆。而智能体学到的那些流程步骤，成为程序性记忆。下一课我们会聚焦最后这一类：把经验变成可复用的技能。我们之前和 DeepLearning.AI 合作的、关于构建有记忆感知的智能体的课，深入讲过这部分。如果你想了解更多，欢迎去看看。
> Let's also see the different types of memories our agents can have. We can put these memories into four categories. First, the messages and tool results being used right now are working memory. Also, anything that happened in previous agent runs becomes episodic memory. The project-specific facts and knowledge becomes semantic memory, and the workflow steps that are learned by the agent become procedural memory. In the next lesson, we can focus on that last one, turning experience into reusable skills. Our previous course with DeepLearning.AI on building memory-aware agents covers this in depth. Feel free to check this out if you want to learn more.

### 长期记忆的原料是轨迹：轨迹是一次智能体交互里每一个事件的完整记录；拿"跑 Python 测试"这个任务举例，它记录下智能体查看过的项目文件、为解决问题采取的动作、这些动作的结果、以及智能体做的修正——这些轨迹就是学习的原材料

> 那这些长期记忆要怎么建呢？我们从轨迹开始。轨迹是一次智能体交互里发生过的每一个事件的完整记录。我们来看一个轨迹的例子和它的组成部分。想象我们的编码智能体有一个要解决的任务，比如在我们的代码库上跑 Python 测试。它记录下智能体在做这个任务时查看过的项目文件。我们还有一份记录，是解决问题所采取的动作、这些动作的结果、以及智能体做的修正。我们可以把这些轨迹当作学习的原材料。
> So how do we build these long-term memories? We start with traces. A trace is a complete record of every event that occurred within an agent interaction. Let's see an example of a trace and its components. Imagine our coding agent has a task to solve. For an example, running Python tests on our code base. It records the project files the agent inspected while working on the task. We also have a record of the actions that were taken to solve the problem, the outcomes from these actions, and the corrections taken by the agent. We can use these traces as raw materials for learning.

### 该从哪儿下手：先问"更好的上下文和指令，能不能提升智能体的表现"；能的话就走token space adaptation（词元空间适应）的两条路——先建一个增强循环让技能适应变强，再用知识图谱搭自适应记忆；如果这些手段都用尽了还是不行，才轮到weight space（权重空间）里对模型本身的增强，那是最后一课的重点

> 最后，如果你想让智能体随着时间变强，应该先在哪里下手？你该问的主要问题是这个：更好的上下文和指令，能不能提升你智能体的表现？如果能，那你就可以用我们归为**token space adaptation（词元空间适应）**的两个主要手段。第一，建一个增强循环，让你智能体的技能适应并变得更好。然后，用知识图谱搭一套自适应记忆。接下来三课我们会看到这些。如果这些手段都被用尽了，再没有什么能让智能体变得更好，那我们才会去看模型本身在**weight space（权重空间）**里还有哪些可能的增强。这会是最后一课的重点。
> Lastly, if you want your agents to improve over time, where should you intervene first? The main question you should ask is this, can better context and instructions enhance your agent's performance? If so, then you can use the two main methods that we group as token space adaptation. Firstly, you will create an enhancement loop to make your agent's skills adapt and get better. Then you will build adaptive memory using a knowledge graph. We will see these in the next three lessons. If these methods have been exhausted and nothing more can be done to make the agent get better, then we will focus on any possible enhancements in the model itself within the weight space. This will be our focus of the last lesson.
