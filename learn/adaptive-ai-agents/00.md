## 全课主线

整门课解决的是智能体的一个致命短板：**每次会话都从零开始**。昨天花半小时踩明白的坑，今天开个新对话，还得再踩一遍——时间、token、还有"这次模型可能推出别的答案"的风险，全白付了。

解法是一把**从便宜到贵的梯子**。先在最便宜的**token space（词元空间）**动手：改行为、改知识，不用碰模型本身；这两招都用尽了还是不行，才爬到最贵的**weight space（权重空间）**，动模型自己的参数。

```
问题：智能体没有记忆 → 每次运行都从零开始 → 重复踩坑，时间和 token 双输
  │
  ├─ 地基（分P 2）：先分清什么叫"记住"
  │    ├─ 智能体 = 模型 + 外壳（harness）；外壳负责组装上下文、跑工具、写记忆
  │    ├─ 四种记忆：工作记忆 / 情景记忆 / 语义记忆 / 程序性记忆
  │    └─ 长期记忆的原料 = 轨迹（trace）：对话、工具调用、决策、报错、修复
  │
  ├─ 第一层 · 行为适应（分P 3）→ 改【技能】
  │    ├─ 技能归纳管道：轨迹 → 归纳引擎起草 skill.md → 人工审核 → 进技能箱
  │    ├─ 关键设计：人在环上。批准=把提案变成行为；坏技能会天天重犯
  │    └─ 演示：run the tests 技能从 v1 升到 v2，测试全绿
  │
  ├─ 第二层 · 知识适应（分P 4-5）→ 改【检索】
  │    ├─ 诊断：大代码库里写不是瓶颈，【检索】才是
  │    ├─ 三种关系建成知识图谱：import（文件→文件）、call（函数→函数）、co-edit（Git 里一起改）
  │    ├─ 检索两步：锚点（语义相似度找到起点）→ PageRank（沿边扩散排序）
  │    ├─ 实测：多跳问题图检索赢，简单问题不吃亏；httpie 上省 22% 工具调用、36% 更快到第一次正确编辑
  │    └─ 闭环：新提交进来 → 抽新边 → 并库 → 重排，增量成本几乎为零
  │
  ├─ 第三层 · 模型适应（分P 6）→ 改【权重】
  │    ├─ 什么时候才用：拒答某话题、装人设、改语气格式——上下文改不动的行为
  │    ├─ 手段：LoRA 低秩适配（冻住原权重，只训两个小矩阵）+ 量化（32 位压到 4 位）
  │    ├─ 甜点区：训约 1% 的权重。太少学不会，太多【灾难性遗忘】
  │    └─ 演示：Qwen 0.6B + 礼貌 LoRA，14,000 组数据，训 1 小时，适配器只 150MB
  │
  └─ 收尾（分P 7）：行为 + 知识 + 权重，三层都掌握，智能体才会"越用越聪明"
```

## 三层适应一览

| | 行为适应 | 知识适应 | 模型适应 |
|---|---|---|---|
| 改什么 | 技能（skill.md） | 检索结构（代码知识图谱） | 模型权重（LoRA 适配器） |
| 空间 | token space（词元空间） | token space（词元空间） | weight space（权重空间） |
| 成本 | 低 | 中 | 高 |
| 见效 | 立刻，人工审核后自动调用 | 立刻，增量更新几乎零成本 | 要训练，几小时到几千小时 |
| 什么时候用 | 一开始就该做 | 检索找不对文件时 | 前两层都用尽还是不行 |

## 涉及的工具与产品

| 名称 | 是什么 |
|---|---|
| Oracle AI Database 26ai | 底座数据库，存轨迹、存知识图谱（PGQ 属性图 + 向量检索） |
| Oracle Agent Memory（`oracleagentmemory`） | 存轨迹和记忆的 Python 包 |
| LangGraph + Oracle DB | 跑技能归纳循环的编排框架 |
| 代码知识图谱（Code Knowledge Graph） | 用 import / call / co-edit 三种边把代码库连成属性图 |
| PageRank | 从锚点出发沿边扩散，给节点排重要度的算法 |
| LoRA | 低秩适配，只训两个小矩阵的微调技术 |
| 量化 | 把 32 位浮点权重压到 4 位，省显存 |
| Claude Code | 实验里驱动智能体的编码工具，配 Sonnet 和 Haiku 两个模型 |
| Qwen 0.6B | 第 6 讲的底座模型，6 亿参数，量化后占约 1GB 内存 |
| httpie / Django | 两套用来做基准测试的开源代码库 |

## 写作规范（与《AI-native SDLC playbook》一致，后续复用）

- **通俗化标准**：正文要让没接触过软件工程的人（初中生水平）也能看懂。英文术语和难懂的专业词第一次出现时，直接在后面加括号写中文释义，让读者不用回头查；不另设《名词解释》章节。不用比喻，也不用指意不明的词。
- **小节顺序**：中心思想 → 逻辑框架 → 核心要点 → 分段详解。逻辑框架放在前面，读者只看这一节就能明白整篇在讲什么。四个小节并存，不互相替代。
- 汇总类小节（中心思想、核心要点、逻辑框架）用白话重写；分段详解保持忠实翻译，英文原文一字不动，只把中文改口语。
- 原文里的表格，译成中文表后再附一份英文原表。代码块、配置文件、提示词保留英文原样，另附中文对照或逐段说明。
- 核心产物名不译：skill、skill.md、trace、harness、PageRank、LoRA。
