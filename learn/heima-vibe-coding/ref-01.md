## 第一阶段：补齐盲区

### [14] Rewind 命令回退代码 —— 会话级别的"时光倒流"

**一句话：** 双击 ESC 回到任意历史对话节点，不依赖 Git 存档点就能精准撤销某一次对话的修改。

**内容拆解：**

| 小节 | 讲什么 |
|------|--------|
| 场景设定：改名演示 | 先把 APP 名从"黑马记账"改为"记账App"，为后续回退做准备 |
| /diff 命令 | 查看本次代码修改的所有差异——8 个文件被改了什么，减号旧内容、加号新内容一目了然。**注意：这个命令只在终端里能用，VS Code 插件不支持** |
| Rewind 核心操作 | 双击 ESC → 弹出历史对话列表 → 选择"请帮我把APP名字改为记账APP"这个节点 → 点击 Continue → 代码回到该对话**还没回车执行**的时间点 |
| Rewind vs Git 对比 | Rewind 适合"只想撤销某一次对话"，Git 存档点适合"回退大量修改到已知版本"。两者互补，不互斥 |

**你学完能做什么：** AI 改崩了代码，不用回 Git 存档（那会把之后的好修改也丢了），直接 Rewind 到改崩前的那一次对话。

### [16] 创建代码分支与执行代码审查 —— 安全实验 + 代码质量保障

**一句话：** 开分支做实验性功能 + 用 `/review` 让 AI 审查自己的代码，严重/中等 Bug 必须修完才合并。

**内容拆解：**

| 小节 | 讲什么 |
|------|--------|
| Git 分支类比 | RPG 游戏副本存档：主线（master）稳定不动，分支（branch）是独立副本，随便改不影响主线。改满意了合并回来 |
| 创建贪吃蛇分支 | 让 AI 创建 `snake-game` 分支，全程不说 Git 命令，只说"帮我开辟一个新分支叫 snake-game" |
| 在分支上开发 | AI 列出三种方案（纯手写/Canvas 库/游戏框架），推荐方案 A，自动写代码并启动验证 |
| Code Review 功能 | **核心新东西：** `/review` 命令调用专用 Agent，逐行差异扫描，输出严重/中等/轻微/建议四级 Bug |
| 审查结果修复 | AI 检测到舌头碰撞误判和双循环性能问题，要求修复后重新验证 |
| 分支合并+推送 | 功能稳定 → commit 存档 → 合并回主线 → 推送到 Gitee |

**你学完能做什么：** 实验性功能开分支搞，不污染主线；每次合并前先 `/review` 自动审查。

## 第二阶段：升级核心能力

### [12] Memory 记忆管理 —— 跨会话的永久偏好系统

**一句话：** 上下文是"短期便签"，记忆是"长期笔记本"。把偏好规则写进硬盘，换项目换会话都自动生效。

**内容拆解：**

| 小节 | 讲什么 |
|------|--------|
| 上下文 vs 记忆 | Context = 会话级，仅当前对话有效；Memory = 硬盘文件，永久保存。类比：短期便签 vs 长期笔记本 |
| 记忆的应用场景 | 把"我是技术小白""所有方案列出来让我选""每个技术点先解释再执行"写入用户记忆，以后任何项目 AI 都自动遵守 |
| 三种管理方式 | `/memory` 命令 → 终端管理界面 → 工程记忆（`CLAUDE.md`）/ 用户记忆（`memory.md`）/ Auto Memory（自动记忆） |
| 让 AI 配置记忆 | 不懂记忆怎么写？直接说"帮我记录为用户记忆"，AI 读取现有文件、判断当前只有项目级、升级写入为全局记忆、自动验证 |

**你学完能做什么：** 把"我是有经验的开发者""代码注释保持简洁""不要主动重构我没提到的代码"写进用户记忆，所有项目自动生效。

### [19] 数字员工测试专家 Subagent 开发 —— 创建能自动调度的专属测试员

**一句话：** 创建一个 tester Subagent，跟 Claude Code 说"帮我跑测试"，主 Agent 自动识别意图并委派给测试专家执行，不占主对话上下文。

**内容拆解：**

| 小节 | 讲什么 |
|------|--------|
| Subagent 概念 | 主 Agent = 项目经理，Subagent = 专家小组。主 Agent 判断任务类型后自动调度对应的 Subagent |
| Subagent 工作原理 | Subagent 独立运行，拥有自己的上下文，不和主对话串混。可以同时并行多个 Subagent |
| 技能 vs Subagent | 技能 = 手动调用的快捷指令（斜杠触发）；Subagent = AI 自动判断并调度的独立 Agent（自动路由）。存放位置也不同 |
| 创建 tester Subagent | 在 `.claude/agents/` 下创建 `tester.md`，用自然语言描述身份（单元测试专家）、技能（unit-test）、工作方式和输出格式 |
| 自动调度验证 | 重启后说"帮我执行一下单元测试"，主 Agent 自动委派给 tester，全程不需手动指定用哪个 Subagent |
| 并行工作能力 | 可以同时派出多个 Subagent —— 测试工程师 + 质量工程师同时干活 |

**你学完能做什么：** 以后说"跑测试"不用自己手动调技能，主 Agent 自动识别、自动委派、独立上下文执行。

## 第三阶段：质变 —— 自动化质量门控

### [20] 数字员工质量工程师 Subagent 开发 —— 多技能组装的数字审查员

**一句话：** 给质量工程师配两个技能（注释检查 + 安全审计），再加内置审查规则，组装成一个自动输出质量报告的 Subagent。

**内容拆解：**

| 小节 | 讲什么 |
|------|--------|
| 质量工程师职责规划 | 五个维度：注释覆盖率（3:7 比例）、注释匹配度、小白可读性、编程规范、安全漏洞（密码泄露等） |
| 创建 comment-check 技能 | 三个检查维度（覆盖率/准确度/可读性）+ Few-shot 示例。注释放到 SKILL.md 即成为可复用技能 |
| 创建 security-audit 技能 | 五个维度：敏感信息泄露、SQL 注入、配置文件安全、Electron 桌面安全、XSS/不安全随机数/eval 等 |
| 组装 quality-engineer | 将两个技能 + 内置规则（错误处理/数据库操作/输入校验/类型检查/重复代码）组合成一个 Subagent |
| 执行质量审查 | 说"帮我审查代码质量"→ 自动路由到质量工程师 → 输出质量报告（总分 61 分，安全无高危，注释严重不足） |
| 自动修复 | 根据报告让 AI 自动补注释，大量中文注释自动生成 |

**你学完能做什么：** 一个命令让 AI 全面审查代码质量，输出打分报告，还能自动修复问题。

### [21] 自定义 Hook 钩子拦截 Git 提交 —— 全课程含金量最高的工程化实践 ⭐

**一句话：** 在 Git 提交前自动跑测试+质量审查，两个都通过才放行，不通过就自动修复直到通过。实现了"AI 自己管质量"的闭环。

**内容拆解：**

| 小节 | 讲什么 |
|------|--------|
| Hook 基本概念 | PreToolUse 拦截机制——在工具调用前触发检查。需求：每次 Git 提交前必须通过测试和质量检查 |
| 通行证机制设计 | 测试和质量工程师完成后各生成一个 PASS/FAIL 标记文件。Hook 检查两个文件都是 PASS 才放行，用后立即销毁（一次性） |
| 三件事规划 | ①添加 Hook 拦截 Git commit；②改造 tester 和 quality-engineer 生成通行证；③新建 git-commit Agent 编排全流程 |
| Plan 模式讨论方案 | 先不执行，切换到 Plan 模式让 AI 产出规划文档，讨论确认后再动手——避免返工 |
| 纠正 AI 方案 | AI 初版方案在 git-save 技能里嵌入了 Agent 调用（破坏了技能独立性）。纠正：技能保持纯粹，Hook 只做判断 |
| 实施：编写 Hook 配置 | 在 `.claude/settings.json` 中添加 hooks 配置，正则匹配 Git commit 命令，执行检查脚本读通行证 |
| 创建 git-commit Agent | 全自动编排：清理旧通行证 → 并行启动测试+质量检查 → 等待结果 → 读通行证 → PASS 则提交 → 销毁通行证 |
| Windows 兼容性调试 | Bash 脚本→PowerShell→最终改为 Agent 模式判断。实战中踩坑和修复全过程 |
| 修复 Hook 匹配规则 | git add + git commit 组合命令的匹配问题，正则从"git commit 开头"改为"*git commit*"通配 |
| 多轮修复直至通过 | 质量检查不通过 → AI 自动修复 → 再检查 → 直到两个 PASS → Hook 放行 → 提交成功 |
| 总结 | Hook+通行证 = 代码质量门控：每次存档必经测试+审查，从源头保证质量。三个 Subagent 各有分工协同 |

**你学完能做什么：** 你说"提交代码"，AI 自动跑测试 → 自动跑质量审查 → 不通过自动修复 → 全通过才提交。全程不需要你盯着。

## 第四阶段：拓宽视野

### [17] 自定义 Skills 技能 —— 项目级 vs 全局级 + 热加载

**一句话：** 你可能写过 Skill，但知道项目级和全局级的区别吗？知道 `/reload-skills` 不用重启就能加载新技能吗？

**内容拆解：**

| 小节 | 讲什么 |
|------|--------|
| 斜杠命令本质 | 斜杠命令 = 固定化操作的快捷方式。把"启动APP""重新打包""Git提交推送"封装成 `/run-app` `/rebuild-app` `/git-save` |
| 避免污染上下文 | 为独立任务创建新 Session，不要把配置技能和开发代码混在同一对话里 |
| 创建 run-app 技能 | 三步启动：确认依赖 → 启动开发服务器 → 验证。存为 `.claude/skills/run-app/SKILL.md` |
| 技能生效条件 | 新技能需重启 Claude Code 或 `/reload-skills`，否则提示"未知命令" |
| 创建 rebuild-app 技能 | 四步打包：清理旧文件 → 确认依赖 → 编译打包 → 确认结果 |
| 项目级 vs 全局级 | 项目级放 `.claude/skills/`（仅当前项目）；全局级放 `~/.claude/skills/`（所有项目通用，如 git-save） |
| 创建全局 git-save 技能 | status → add → commit → push 四步标准化，输入 `/git-save` 一键完成 |

**你学完能做什么：** 把常用操作封装为全局 Skill，换项目也能用；知道 `/reload-skills` 不用重启。

### [28] Qoder 的 Git 集成与 Skills 及 Subagent 开发 —— 换工具看看差异

**一句话：** Qoder（阿里出品）和 Claude Code 功能大同小异，但有一个 Claude Code 没有的优势——Skills 创建后立即生效，不需要 reload。

**内容拆解：**

| 小节 | 讲什么 |
|------|--------|
| Qoder Git 集成 | 把 Gitee 仓库信息全丢给 Qoder，AI 自动初始化、提交、推送，完全不用手动操作 |
| 上下文管理差异 | Qoder 没有手动 `/context` 和 `/compact`，系统自动压缩——属于"自动挡"模式 |
| Skills 开发 | 创建 git-save 技能，流程和 Claude Code 一样 |
| **Skills 热加载** | Qoder 创建 Skills 后立即生效，不需要 `/reload-skills`——比 Claude Code 先进一点 |
| Subagent 开发 | 创建 TestRunner，流程和 Claude Code 一样。52 个测试用例全部通过 |

**你学完能做什么：** 知道不同工具之间的差异点，选型时有依据。热加载这个特性也可以在跟 Claude Code 团队提反馈时引用。

### [31] CodeX 基础功能全景对比 —— 三工具横向评测

**一句话：** Claude Code vs CodeX vs Qoder，核心功能大同小异，差异在工程化精细度。

**内容拆解：**

| 小节 | 讲什么 |
|------|--------|
| VSCode 受限模式 | 新项目需手动点"信任"才能激活插件 |
| CodeX 全局记忆 | 没有内置全局记忆，但支持 `.codex/memory.md` 文件实现，类似 CLAUDE.md |
| 上下文管理 | CodeX 自动压缩，没有手动触发命令——后发优势 |
| Git 集成 | 流程一样，但注意用 SSH 地址而非 HTTPS 以免弹密码框 |
| 横向对比评测 | Claude Code 100 分，CodeX 约 95 分——差异不在模型（都用 DeepSeek V3 Pro），而在工具的工程化精细度 |
| 课程总结 | Vibe Coding 工具核心功能大同小异，关键在工程化精细程度；选顺手的即可 |

**你学完能做什么：** 对自己用的工具有全局认识，知道 Claude Code 的强项在哪里（工程化精细度），短板在哪里（Skills 需 reload、上下文手动管理）。

## 总结：学完前后的变化

| | 学之前 | 学之后 |
|------|--------|--------|
| 撤销改崩的代码 | 回 Git 存档点，之后的好修改也丢了 | 双击 ESC，精准回退到改崩前那一次对话 |
| 代码质量 | 靠肉眼看，或者 AI 写崩了才知道 | `/review` 自动审查 + 质量工程师输出打分报告 |
| 提交代码 | 说"帮我提交"，直接提交 | Hook 拦截 → 自动跑测试 → 自动跑审查 → 不通过自动修复 → 全通过才放行 |
| 重复操作 | 每次都说一遍需求 | 封装为全局 Skill，换项目也能用 `/技能名` 一键执行 |
| 测试 | 想起来才跑 | 说"跑测试"自动委派给 tester Subagent，独立上下文不污染主对话 |
| 跨项目一致性 | 每个项目重新交代偏好 | 用户记忆全局生效，新项目自动遵守 |
