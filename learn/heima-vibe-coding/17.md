## 十七、自定义Skills斜杠命令——将固定操作封装为可复用的快捷技能，实现项目级和全局级工程化控制

### Claude Code内置斜杠命令与自定义技能的概念——斜杠命令本质是固定化操作的快捷方式，通过创建SKILL.md文件可将日常重复操作（如启动应用、打包、Git提交）封装为可一键调用的技能，技能分为项目级（存放在项目.claude/skills/目录）和全局级（存放在用户目录.claude/skills/目录）

> Hello，小伙伴们大家好，欢迎回来。
> 本期我们来学习自定义斜杠命令。
> 那我们当前用了这个Claude Code，你会发现它里面有个内置的斜杠，
> 那这个斜杠你点开之后的话呢，其实有很多内置的一些常见快捷命令，
> 这些命令都是一些固定化的操作，比如说斜杠 Code Review，
> 其实本质就是触发它的代码审查动作；
> 还有像我们的斜杠 /context 的，其实就触发了它的一个叫做上下文的检查。
> 那其实在我们当前的项目里面也是有很多的固定动作的，比如：把我的APP给我运行一下，
> 又或者说把我的APP重新打包，重新生成最新的 .exe 安装文件，
> 又或者把我们的代码给它推送到Gitee上、给我们打一个存档点等等。
> 那这些动作呢都是固定操作，并且也是经常会用到的。
> 那我们这种固定操作和经常会用到的就可以把它配置为斜杠命令。
> 那这个斜杠命令如何配呢？其实本质上来说就是你给它添加一个自定义的叫 Skills 技能就行了，
> 就是把我们想要做的操作给它配置为Claude Code的技能。
> 那配置好技能之后的话呢，就可以让我们配的这个技能以斜杠的模式直接就调用了。

### 使用新对话避免污染——在与Claude Code协作时，应该为独立任务（如配置技能、询问技术问题）创建新的Session，避免将不同类型的问题混在同一个开发对话中污染上下文，保持每个对话的专注性

> 那如果说你不知道怎么做，我们正常情况下肯定是先问一下Claude Code对吧？
> 因为我们说我们是领导，它是员工，有啥不懂的直接问它，让它帮我们去解释就行了。
> 那么在下面其实可以正常直接打字去问，但是我们想了一下：我们当前的APP，主体上来说这个对话框里面都是跟APP功能开发相关的，所以为了避免不污染这个对话，我们还是创建一个新的对话专门去做这些独立的事情。
> 要不然的话你在这个对话里面又写代码，又玩自定义斜杠的什么 Skills 命令等等，又问上问题，那这个对话就会被污染。
> 在我们这个VSCode的这个插件里面，它有两个Claude Code——你看左边一个是我们当前正在对话的一个内容，右边其实就是所有的会话管理。所以它两个页面，右边的会话管理，我们可以点击这个叫 New Session 来创建一个新的会话。

### 询问Claude Code如何自定义技能——作为小白可以直接向Claude Code提问"如何自定义技能"，它会查阅知识库或联网搜索，给出详细的步骤说明：技能文件SKILL.md存放在.claude/skills/技能名/目录下，用自然语言描述技能行为即可

> 那我们现在就问一下它一个简单的问题：就是我想要自定义技能，然后方便使用斜杠调用它，那么如何做呢？
> 也帮我看看。我们相当于就是我有这个需求，但我不知道具体怎么做，你可以去问一下Claude的，那它就会去查阅它自己的一些知识库，又或者说去联网去搜索相应的资料，然后告诉你怎么样去自定义技能等等。
> 那技能存放的位置呢其实有两个地方：第一个就是你的项目的根目录，就是在我们项目里面有个叫 .claude 的文件夹，在这里面创建个叫 skills 的一个文件夹，然后再创建一个技能名的文件夹，在技能名的文件夹里面去放 SKILL.md，这就是技能的核心文件。
> 那 SKILL.md 其实本质上来说就是一个文本文档，就是一个Markdown文件，那这里面就写好了你要做的一些提示词。也就是说，当你去触发这个技能的时候，本质等于你对它说了什么事。
> 以自然语言的形式去描述技能就行了，不需要你有专业的东西，你就按照自然语言的行为去描述这个技能就可以。

### 创建第一个项目级技能run-app——通过Claude Code自动创建技能文件，技能描述包含启动步骤（确认依赖安装、启动开发服务器、验证成功），创建后需重启VSCode使技能生效，之后输入/run-app即可一键启动应用

> 那它现在询问我：是不是帮我创建一下？那我说是的。那么在执行之前呢，我们先把这个会话先给它转移到我们右侧这边。
> 在我们右侧这边你可以看到这个有一个叫做小时钟的东西，这个小时钟你看到就能找到我们刚刚左边的叫"自定义技能调整方法"的会话。
> 好，那我们给它说一下来：就是帮我们创建这个叫 run-app 技能。
> 好的，那我们给它说了一下之后的话，它就会去读取我们当前的一些代码，然后看看你代码里面到底怎么写的，然后来决定怎么去启动。
> 然后它问我是否允许去执行对应的命令——你看那个命令叫 mkdir，就是创建文件夹，它在我们的 .claude 里面去创建一个叫做 skills 的文件夹，在里面再创建一个叫做 app 的文件夹。
> 好，那可以看到这里面它是准备好了这个叫 SKILL.md 的一个文档，这就是我们的技能。
> 其实说明了所谓的技能是什么：所谓的技能就是把你日常你跟Claude Code的一个聊天、或者说你的要求变成一个快捷指令。
> 比如如果没有这个技能，你怎么样让它帮你启动呢？你可能就跟Claude聊天说"你帮我启动一下我这个黑马记账的APP"，你是不是要写这句话呀？
> 那现在你给它转成技能了，相当于就是你的斜杠叫 run-app 就等于你说的这句话。

### 技能生效需要重启Claude Code——新创建的技能文件不会立即被识别，因为Claude Code在启动时加载技能列表，需要重启VSCode（本质是重启Claude Code程序）或使用/reload-skills命令重新加载

> 那当我们运行的时候你看，它发现了说叫"未知的命令"，它说不知道这个命令。那这是怎么回事呢？这个是正常的，因为我们那个技能是刚刚创建的，然后Claude是已经提前加载了、已经运行好了。所以很简单，我们只需要把我们的Claude重启一下，那么它启动之后的话就会读取我们的技能包里面有什么东西了。
> 所以我们可以把我们的VSCode给关闭，然后重新打开就可以了。
> 好的，我的Claude目前呢是已经刚刚重启了，那么再来执行 run-app。你看到，当我们重启之后，它是不是就有自动提示有这个命令的呀？
> 现在再来运行，它就可以按照我们这个 SKILL.md 里面的描述，一步一步地去把我们程序启动起来。比如你看我们的描述三个步骤：依赖、还有开发服务器、还有验证，你看它第一步检查依赖，第二步启动开发服务器，第三步直接把我们的程序运行起来。

### 创建rebuild-app打包技能——第二个项目级技能用于将应用重新打包生成最新版.exe安装文件，包含清理旧文件、确认依赖、编译打包、确认结果四大步骤，同样创建后需重启生效

> OK，那完了这个技能定义之后呢，那我们同样让它再帮我们再创建另外一个技能。那另外一个技能就是：帮我再创建一个技能，然后技能名字叫做 rebuild-app，
> 那它的功能呢就是将我们的APP重新打包，打包一份、重新打包一份就可以了。OK，那它帮我们把这个技能给创建出来，那这样的话方便我们后续如果你有需要的话直接去执行那个叫做 rebuild-app 的命令就可以快速地帮我们整个APP进行重建。
> 它那个 SKILL.md 描述了也搞定了，你看叫"重新打包应用生成 .exe 安装文件"，然后打包步骤：清理旧的、确认依赖、编译打包、确认打包结果，主体就是这四大步骤。
> OK，那重新完之后我们再来去执行叫 rebuild-app，直接回车。可以看到我们的技能已经加载进来了，然后现在它就开始去按照我们所规划的技能去执行：比如说清理啊、确认依赖啊、编译打包啊等等。

### 项目级技能与全局级技能的区别——项目级技能存放在项目根目录的.claude/skills/下，只对当前项目生效；全局技能存放在用户目录的.claude/skills/下，对所有项目都生效，适合Git提交推送这类跨项目的通用操作

> 那我们再额外说一下：我们当前所制作的这个技能啊，其实是只能够针对于当前项目的。
> 来，同学们想一想，我们当前所写的这些技能，你看它的文件夹在什么地方？在我们当前项目的文件夹，然后里面有个叫 .claude 的，然后里面有个叫 skills 的，然后在这个里面就有我们的两个技能包对吧？
> 那就是说明我们当前所写的这些技能是只能针对于"黑马记账App"的，也就是当Claude Code去加载的这个文件夹，它才能加载这个技能。那如果说我们换了项目，这个技能呢就不通用了。
> 所以如果你想要去得到通用的技能，也就是不论什么项目都能使用的技能——比如我们的Git的一个 commit 和 push 提交对吧，像这种命令，我们不管是任何项目，肯定都用得上的。
> 那这种跨项目通用型的技能呢，就肯定是要换地方存放的。那需要换哪里存放呢？就是把我们技能的文件给它换个地方放就行。

### 创建全局技能git-save——在用户目录的.claude/skills/下创建git-save技能，包含git status查看变更、git add暂存、git commit提交、git push推送远程四步标准化Git操作流程，实现一键存档推送

> 那现在我们知道怎么做的话呢，我们就来去做一个技能：就是帮我们写一个全局的技能，然后名字叫 git-save，就是用Git去保存我们的存档点。然后功能呢是用Git进行存档然后并推送到远程服务器上。
> 把我们这一套固定流程呢给我们做一下，这叫 git-save 的，只不过我们当前这个技能需要帮我们写到全局里面。
> 那么在编辑之前，我们可以先来检查一下我们当前那个文件夹里面内容有哪些。比如我打开我的这个文件管理器，在我当前C盘用户、我的用户名下 .claude，可以看到这个里面目前还是没有这个叫 skills 的相关的东西的。
> 可以看到这个叫 skills 的夹子就帮我们自动创建好了，然后里面你看 git-save 也创建好了。
> 好你看，技能搞定了！进来之后你看这里有个叫 git-save 里面叫 SKILL.md 的，我们双击打开看看 .md 里面到底写的是什么东西。
> 好，进来之后的话，你看这是我们当前的一个技能，它的名字叫 git-save，然后描述就是"推送至远程仓库"，然后执行步骤就是：先 git status 看看哪些文件，然后 git add 暂存所有修改，然后 git commit 去提交，然后 git push 去推送到远程仓库。
> 所以以后当我们每次想把代码去打存档点、推送到服务器的时候，你不需要噼里啪啦再说一句话，你只需要输入斜杠 git-save 就可以完成这个自动的动作了。
