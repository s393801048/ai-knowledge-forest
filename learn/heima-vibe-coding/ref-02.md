> 整理自黑马 Vibe Coding 零基础入门课程 [11]-[18] 课，涵盖 Git 版本控制、上下文压缩、记忆管理、Rewind 回退、远程推送、分支开发、代码审查、Skills 技能、Agent 智能体九大模块。

## 一、Git 版本控制 —— 代码的"存档系统"

### 1.1 基础命令

| 命令 | 作用 | 说明 |
|------|------|------|
| `git init` | 初始化本地仓库 | 在项目目录执行，开启"存档系统" |
| `git add .` | 暂存所有文件 | 把文件加入版本控制 |
| `git commit -m "说明"` | 保存存档点 | 相当于按下"保存按钮"，用大白话命名即可 |
| `git log` | 查看存档历史 | 列出所有 commit 记录 |
| `git checkout <文件>` | 从存档恢复单个文件 | 代码写崩了还原用 |
| `.gitignore` | 排除不需要存档的文件 | `node_modules/` `out/` `dist/` `.db` 等不存档 |

### 1.2 分支操作

| 命令/方法 | 作用 | 说明 |
|----------|------|------|
| 让 AI 创建分支 | "帮我开辟一个新分支叫 xxx" | AI 自动执行 `git branch` + `git checkout` |
| `git branch` | 查看所有分支 | 确认当前在哪个分支上工作 |
| 分支合并 | "帮我把分支合并到主线上" | AI 自动执行 `git merge` |

### 1.3 分支概念

| 概念 | 含义 | 类比 |
|------|------|------|
| 主线（master） | 稳定的主代码 | 始终可运行的版本，不直接在上面做实验 |
| 分支（branch） | 从主线复制的独立副本 | RPG 游戏"复制存档走支线剧情"；修改重要文档前先复制副本 |

### 1.4 远程推送

| 命令/方法 | 作用 | 说明 |
|----------|------|------|
| 新建仓库 | 在 Gitee 创建远程仓库 | gitee.com → 右上角加号 → 新建仓库 |
| 添加 SSH 公钥 | 配置免密推送 | 网站设置 → SSH 公钥 → 粘贴公钥 |
| 让 AI 检查/创建密钥 | 自动获取 SSH 公钥 | "帮我看看电脑有没有可用的公钥私钥" |
| `git push -u origin master` | 推送本地代码到远程 | `-u` 记录路线，`origin` 远程仓库名，`master` 分支名 |
| 让 AI 解释命令 | 执行前先理解命令含义 | "这个命令是什么意思？解释一下我再决定是否执行" |
| 让 AI 生成 README.md | 自动编写项目说明文档 | AI 扫描项目代码和 CLAUDE.md 后自动生成 |

> **🔐 为什么用 Gitee：** GitHub 国内访问不稳定，Gitee 是国内替代品，注册即用。
>
> **🛡️ 双重保险：** 本地 Git 存档 + Gitee 远程同步 = 磁盘坏了/换电脑都不怕。
>
> **📦 一句话推送：** "帮我本地打存档，然后推送到 Gitee"

## 二、上下文管理 —— 保持 AI 对话健康

| 命令 | 作用 | 说明 |
|------|------|------|
| `/context` | 查看上下文使用量 | 显示 token 占用百分比（DeepSeek V4 Pro 支持 100万 token 上限） |
| `/compact` | 压缩对话历史 | 去细节留关键节点，大幅降低上下文占用 |

> **🔁 推荐工作流：** 完成一个功能节点 → `git commit` 打存档 → `/compact` 压缩上下文

## 三、记忆管理 —— 跨会话的永久偏好

### 3.1 记忆类型

| 命令/方法 | 作用 | 说明 |
|----------|------|------|
| `/memory` | 打开记忆管理界面 | 在终端中执行，可选择工程/用户/自动记忆 |
| 工程记忆 (`CLAUDE.md`) | 仅当前项目生效 | 存放在项目根目录 `.claude/CLAUDE.md` |
| 用户记忆 (`memory.md`) | 跨项目、跨会话全局生效 | 存放在用户目录 `~/.claude/memory.md` |
| Auto Memory | 自动记忆功能 | 可开启/关闭，AI 自动记录偏好 |
| 让 AI 配置记忆 | 直接说"帮我记录为用户记忆" | 不需要自己写文件，AI 自动编辑 |
| 验证记忆 | 读取并显示记忆文件内容 | 或手动打开 `~/.claude/memory.md` 查看 |

### 3.2 核心概念

> **💡 核心区别：** 上下文（Context）= 短期便签，仅当前会话有效；记忆（Memory）= 长期笔记本，写进硬盘永久保存，换项目换会话都生效。
>
> **🎯 典型用法：** 把"我是技术小白""所有技术方案列出来让我选""每个技术点先解释再执行"写入用户记忆，以后任何项目 AI 都自动遵守这些规则。

## 四、Rewind 回退 —— 会话级"时光倒流"

### 4.1 命令速查

| 命令/方法 | 作用 | 说明 |
|----------|------|------|
| `/diff` | 查看代码修改差异 | **仅终端支持**，VS Code 插件中不可用 |
| `双击 ESC` | 打开 Rewind 历史对话列表 | 显示所有历史输入节点，选择一个即可回退 |
| `Continue`（确认回退） | 确认回退到选中节点 | 代码恢复到该对话**刚输入但未回车执行**的时间点 |

### 4.2 Rewind vs Git 存档点

| 方式 | 适用场景 | 特点 |
|------|---------|------|
| **Rewind**（双击 ESC） | 只想撤销某一次特定对话的修改 | 精细回退，任意节点自由跳转，无需提前存档 |
| **Git 存档点**（`git checkout`） | 回退大量修改或多个版本 | 需要提前打存档，回退到已知的稳定版本 |

> **💡 终端进入方式：** 在项目文件夹 `Shift + 右键 → 在终端打开 → 输入 claude`，即可使用完整命令（含 `/diff`）。

## 五、代码审查 —— 专业的代码质量保障

### 5.1 审查命令

| 命令/方法 | 作用 | 说明 |
|----------|------|------|
| Code Review（`/review`） | Claude Code 内置代码审查 | 调用专用 Agent，逐行差异扫描（line by line diff scan） |
| 审查结果等级 | 严重 / 中等 / 轻微 / 建议 | 严重和中等必须修复后再合并 |
| 修复后重新验证 | 审查 → 修复 → 再审查 | 直到问题清零 |

### 5.2 完整分支开发闭环

```
主线存档 → 创建分支 → 在分支上开发 → Code Review 审查
→ 修复 Bug → 功能稳定 → commit 存档 → 合并回主线 → 推送到 Gitee
```

> **💡 什么情况用分支：** 实验性功能、与主线无关的新功能、怕改崩主线代码时。

## 六、完整工程化循环

```
描述需求 → AI 列出方案 → 选择方案 → AI 开发
→ 测试验证 → 发现 Bug 反馈修复 → 测试通过
→ git commit 打存档 → /compact 压缩上下文
```

> **小白工作法：** 不懂技术没关系，你是领导、AI 是员工。每一步让 AI 先解释再执行，你做最终拍板。

## 七、自定义 Skills 技能 —— 一键调用固定操作

### 7.1 技能核心概念

| 概念 | 说明 |
|------|------|
| 技能本质 | 把日常重复操作封装为斜杠命令，输入 `/技能名` 即可一键执行 |
| 技能文件 | `SKILL.md`，用自然语言描述技能行为即可，不需要专业技术 |
| 存放位置 | 项目级：`.claude/skills/技能名/SKILL.md`；全局级：`~/.claude/skills/技能名/SKILL.md` |
| 生效方式 | 重启 Claude Code，或使用 `/reload-skills` 重新加载 |

### 7.2 项目级 vs 全局级

| 类型 | 存放位置 | 生效范围 | 示例 |
|------|---------|---------|------|
| 项目级 | 项目 `.claude/skills/` | 仅当前项目 | `/run-app` `/rebuild-app` |
| 全局级 | 用户目录 `~/.claude/skills/` | 所有项目通用 | `/git-save` |

### 7.3 推荐技能模板

| 技能名 | 功能 | 核心步骤 |
|--------|------|---------|
| `run-app` | 一键启动应用 | 确认依赖 → 启动开发服务器 → 验证成功 |
| `rebuild-app` | 重新打包生成 .exe | 清理旧文件 → 确认依赖 → 编译打包 → 确认结果 |
| `git-save` | 一键存档并推送 | `git status` → `git add .` → `git commit` → `git push` |

> **💡 创建技能：** 告诉 Claude Code "帮我创建一个技能叫 xxx，功能是……"，AI 自动创建目录和 SKILL.md 文件。
>
> **⚠️ 新技能生效：** 创建后需重启 Claude Code 或执行 `/reload-skills`，否则会提示"未知的命令"。

## 八、Agent / Subagent 智能体 —— 数字员工体系

### 8.1 Agent 三要素

```
Agent = 技能(Skills) + 记忆(Memory) + 模型(Model)
```

| 要素 | 作用 | 谁负责 |
|------|------|--------|
| 技能 (Skills) | 决定 Agent 能做什么 | **你来配置** |
| 记忆 (Memory) | 对话上下文 + 历史信息 | Claude Code 自动管理 |
| 模型 (Model) | 大脑，思考判断 | DeepSeek V4 Pro（已配置） |

### 8.2 层级架构

| 层级 | 角色 | 类比 |
|------|------|------|
| 主 Agent (Claude Code) | 公司 CEO | 路由决策，分配任务给对应 Subagent |
| Subagent（数字员工） | 专业执行者 | 专注某一类任务（测试/审查/安全检查） |

### 8.3 创建 Subagent 要点

| 步骤 | 说明 |
|------|------|
| 先建技能 | Subagent 的能力取决于它拥有的技能，先创建好技能再组装 Agent |
| 描述职责 | 告诉 Claude Code Agent 的名字、职责、可用技能列表 |
| 独立上下文 | Subagent 在独立上下文中工作，输入输出与主对话隔离，保持清爽 |
| 示例技能 | `unit-test`（单元测试）、`comment-check`（注释检查）、`security-audit`（安全审计） |

> **💡 小白心法：** 不知道怎么开发 Agent？直接告诉 Claude Code "帮我创建一个测试工程师的 Subagent"，让它自己给自己开发。

## 十、Claude Code 通用命令补充

> 以下命令来自微信公众号文章《Claude Code 全攻略：命令大全 + 实战工作流》，补充课程未覆盖的通用命令。

### 10.1 启动与环境命令

| 命令 | 作用 | 说明 |
|------|------|------|
| `claude` | 启动交互界面 | 在当前目录启动 Claude Code |
| `claude /path/to/project` | 指定目录启动 | 在指定项目目录启动 |
| `claude --version` | 查看版本号 | 确认当前安装的版本 |
| `claude update` | 升级到最新版本 | 联网更新 Claude Code |
| `claude -c` | 恢复上一次会话 | 次日继续昨天未完成的工作 |
| `/add-dir <目录>` | 添加工作目录 | 让 Claude Code 识别项目目录 |
| `/init` | 初始化项目记忆 | 扫描代码库，自动生成 `CLAUDE.md` 初稿 |
| `/doctor` | 环境健康检查 | 检查 API 连通性、依赖、权限等 |

### 10.2 会话管理命令

| 命令 | 作用 | 说明 |
|------|------|------|
| `/clear` | 清空对话历史 | 完全重置上下文，适合切换到全新任务时 |
| `/compact [提示]` | 压缩上下文 | 保留摘要精华，可指定侧重方向 |
| `/context` | 查看上下文用量 | 显示 token 占用百分比 |
| `/status` | 会话状态检查 | 显示工作目录、账户、模型、加载的记忆 |
| `/cost` | 令牌与费用统计 | 查看 token 消耗和预估 API 费用 |

### 10.3 配置与模型

| 命令 | 作用 | 说明 |
|------|------|------|
| `/config` | 查看/修改配置 | 交互式菜单：主题、自动压缩、通知等 |
| `/model [模型名]` | 切换 AI 模型 | Sonnet（日常）/ Opus（复杂架构）/ Haiku（快速） |
| `/hooks` | 配置自动化钩子 | 如写文件后自动 prettier 格式化 |
| `/help` | 查看命令列表 | 列出所有可用斜杠命令 |

### 10.4 三种工作模式

| 模式 | 切换方式 | 行为 |
|------|---------|------|
| **Default**（默认模式） | 默认 | 每次编辑/执行都需确认 |
| **Auto-Accept**（自动接受） | `Shift+Tab` ×1 | 文件修改自动执行，shell 命令仍需确认 |
| **Plan Mode**（计划模式） | `Shift+Tab` ×2 | 只读模式，只分析规划不做修改 |

### 10.5 任务与快捷键

| 快捷键/命令 | 作用 | 说明 |
|------------|------|------|
| `Ctrl+B` | 后台运行任务 | 让 AI 后台编译/测试，前台继续讨论 |
| `Ctrl+T` | 任务列表面板 | 查看 Claude 创建的任务进度 |
| `/tasks` | 管理后台任务 | 查看/停止后台运行的任务 |
| `Ctrl+G` | 打开计划文件编辑 | 直接编辑 Plan Mode 生成的计划文件 |
| `Ctrl+R` | 切换 verbose 模式 | 查看 Claude 内部推理步骤 |
| `Ctrl+C` | 中断当前操作 | 停止 AI 正在执行的命令 |
| `Shift+Enter` | 输入框内换行 | 输入多行代码或需求时用 |
| `?` | 显示快捷键帮助 | 列出所有可用快捷键 |
| `Alt+V` | 粘贴图像（Windows） | 截图粘贴给 Claude 分析 |

### 10.6 模型选用原则

| 阶段 | 模式 | 推荐模型 |
|------|------|---------|
| 读代码 / 规划 | Plan Mode | Opus |
| 日常编码 | Default | Sonnet |
| 重复性修改 | Auto-Accept | Sonnet / Haiku |
| 快速问答 | Default | Haiku |
