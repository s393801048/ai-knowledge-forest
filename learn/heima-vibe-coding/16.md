## 十六、创建代码分支与执行代码审查 —— 安全的功能实验与专业的代码质量保障

> **📋 本课命令速查**
>
> | 命令/方法 | 作用 | 说明 |
> |----------|------|------|
> | **分支操作** | | |
> | 让 AI 创建分支 | "帮我开辟一个新分支叫 xxx" | AI 自动执行 `git branch` + `git checkout`，无需手动输入命令 |
> | `git branch` | 查看所有分支 | 确认当前在哪个分支上工作 |
> | 分支合并 | "帮我把分支合并到主线上" | AI 自动执行 `git merge` |
> | **分支概念** | | |
> | 主线（master） | 稳定的主代码 | 始终可运行的版本，不直接在上面做实验 |
> | 分支（branch） | 从主线复制的独立副本 | 在副本上随意修改，不影响主线；类似 RPG 游戏"复制存档走支线剧情" |
> | **代码审查** | | |
> | Code Review（/review） | Claude Code 内置代码审查 | 调用专用 Agent 代理，逐行差异扫描（line by line diff scan） |
> | 审查结果等级 | 严重 / 中等 / 轻微 / 建议 | 严重和中等必须修复后再合并 |
> | 修复后重新验证 | 审查 → 修复 → 再审查 | 直到问题清零 |
>
> **🔁 完整分支开发闭环：**
>
> ```
> 主线存档 → 创建分支 → 在分支上开发 → Code Review 审查
> → 修复 Bug → 功能稳定 → commit 存档 → 合并回主线 → 推送到 Gitee
> ```
>
> **💡 什么情况用分支：** 实验性功能、与主线无关的新功能、怕改崩主线代码时
