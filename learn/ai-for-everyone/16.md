## 八、与AI团队协作——帮AI团队成功的关键：用统计方式定义验收标准、理解训练集和测试集的分工、不要期望100%准确率；即使没有AI团队，你和工程师朋友上几门在线课程也能起步

### 与AI团队协作的第一步是明确验收标准——由于AI系统性能通常用统计方式定义（比如检测咖啡杯瑕疵达到95%准确率），你需要准备一个"测试集"来度量这个准确率；测试集是一组带有标注的图片（哪些是好杯子、哪些是次品），AI团队要在测试集上验证是否达到了目标性能；技术上有些AI团队还需要两个测试集（开发和验证集），这是合理的

> 假设你找到了一个想做的有意思的项目，你怎么跟 AI 团队合作呢？这个视频你学到的是 AI 团队如何看待数据，以及你如何与 AI 团队互动来帮他们在项目上取得成功。有个前提要说一下：如果你有一个很酷的点子但接触不到 AI 团队、没有任何 AI 工程师——好在今天这个世界，如果你自己、或者你能鼓励你的工程师朋友去上一两门机器学习或深度学习的在线课程，通常就足以让他们有了起步的知识，可以在这些项目上做出合理的尝试了。那咱们聊聊怎么跟 AI 团队合作。首先，如果你能为项目指定验证标准，这对 AI 团队非常有帮助。我用自动视觉检测来举例——假设你的目标是检测咖啡杯瑕疵，准确率达到至少 95%，这就可以是你的验收标准。但 95% 准确率——怎么度量这个准确率？AI 团队需要的是一个数据集来度量准确率。数据集就是一组图片加上标签——期望输出 B：前两个杯子合格，第三个是次品。所以作为验收标准的一部分，你要确保 AI 团队有一个数据集可以用来度量性能，这样他们才知道是否达到了 95% 准确率。这个数据集的正式术语叫"测试集"，测试集不需要太大，比如一千张图片可能就够了。但咨询 AI 专家，他们会更好地告诉你测试集需要多大才能评估是否达到了 95% 准确率。
> First it really helps your AI team if you can specify an acceptance criteria for the project. I've done a lot of work in automated vision inspection, so I'm going to use that as a running example in these few slides. Let's say your goal is to detect defects in coffee mugs with at least 95% accuracy. So that can be your acceptance criteria for this project. But 95% accuracy, how do you measure accuracy? One of the things the AI team would need is a data set on which to measure the accuracy. So a data set is just a set of pictures, like these, together with the labels with the desired output B that the first two coffee mugs are okay and the third one is defective. So as part of your specification for the acceptance criteria, you should make sure that the AI team has a data set on which to measure the performance so that they can know if they've achieved 95% accuracy. The formal term for this data set is called a test set and the test set may not need to be too big. Maybe a thousand pictures would be just fine for this example. But if you consult an AI expert, they can give you a better sense of how big the test set needs to be for them to be able to evaluate whether or not they're getting to 95% accuracy.

### AI系统的一个新颖之处在于性能通常用统计方式来表达——你不要求系统"完美地"做某件事，而是要求它达到某个百分比准确率、或者在平均意义上表现如何；所以定义验收标准时要想清楚要不要用统计方式

> AI 系统一个新颖的地方在于性能通常用统计方式来定义。你不要求一个 AI 系统完美地做某件事，而更多是要求它在某个百分比准确率上表现——就像这里的例子。所以当你指定验收标准的时候，想一想你的验收标准是否需要以统计方式定义——指定它平均表现如何，或者有多大比例的情况下必须得到正确答案。
> One novel part of AI systems is that the performance is usually specified in a statistical way. So rather than asking for an AI system that just does something perfectly, you see very often that we want an AI system that performs at a certain percentage accuracy, like this example here. So when specifying your acceptance criteria, think of whether your acceptance criteria needs to be specified in a statistical way, where you specify on average how well it does or what percent of time it has to get the right answer.

### AI团队把数据分成两个主要集合：训练集（带标注的样本，机器学习算法从中学习A到B的映射——输入是咖啡杯图片，输出是合格还是次品）和测试集（另一组不同图片也带标注，用来评估学习出来的效果）；比如给测试集的3张图片分别输出合格、合格、合格，实际第三张是次品，那准确率就是2/3即66.7%；实践中训练集通常比测试集大非常非常多

> 咱们深入看看训练集和测试集的概念——这就是AI团队看待数据的方式。AI团队把数据分成两个主要数据集：训练集和测试集。训练集是一组图片加上标签，标明每张图片的咖啡杯是合格还是次品。训练集给出了输入 A（咖啡杯图片）和期望输出 B（合格还是次品）的样例。有了训练集，机器学习算法会学习——也就是"计算"或"找出"——从 A 到 B 的某种映射，这样你就有了一个软件，输入一张图就能尝试判断对应的输出 B 是什么。测试集是另一组不同的图片，也都带着标签。AI 团队评估学习算法的方式是把测试集中的图片输入到 AI 软件中，看它输出了什么。比如测试集有三张图，前两张是合格的、第三张是次品，如果 AI 软件输出都是"合格"，那就是对了 2 个、错了 1 个——66.7% 的准确率。这个图里训练集和测试集都只有三张图片，实践中两个数据集都会大得多。你会发现对大多数问题，训练集比测试集大非常非常多。具体需要多少数据，跟 AI 工程师聊一下。最后，出于技术原因，有些 AI 团队需要的不是一个测试集而是两个——如果你听到他们说"开发集"、"验证集"或"dev 集"，那就是第二个测试集。为什么需要两个测试集的原因比较技术化，超出了这门课的范围。但如果 AI 团队找你要两个不同的测试集，这很合理，尽量提供给他们。
> Let's dive more deeply into the concept of a test set. This is how AI teams think about data. AI teams group data into two main data sets. The first called the training set and the second called the test set, which we've already talked a bit about. The training set is just a set of pictures together with labels showing whether each of these pictures is of a coffee mug that is okay or defective. So the training set gives examples of both the input A, the pictures of the coffee mugs, as well as the desired output B, whether it's okay or defective. And so given this training set, what a machine learning algorithm will do is learn, in other words, compute or figure out some mapping from A to B so that you now have a piece of software that can take as input the input A and try to figure out what is the appropriate output B. So the training set is the input to the machine learning software that lets it figure out what is this A to B mapping. The second data set that the AI team will use is the test set. And as you've seen, this is just another set of images that's different from the training set, also with the labels provided. The way an AI team will evaluate their learning algorithm's performance is to give the images in the test set to the AI software and see what the AI software outputs. For example, if on these three test set images, the AI software outputs okay for this, okay for this, and also okay for this, then we would say that it got two out of three examples, right? So that's a 66.7% accuracy. In this figure, the training set and test set are both only three pictures. In practice, both of these data sets would be much bigger, of course. And you find that for most problems, the training set is much, much, much bigger than the test set. But you can talk to AI engineers to find out how much data they need for a given problem. Finally, for technical reasons, some AI teams will need not just one, but two different test sets. If you hear AI teams talk about development or dev or validation sets, that's the second test set that they're using. The reasons why they need two test sets is quite technical and beyond the scope of this course. But if an AI team asks you for two different test sets, it's quite reasonable to try to provide that to them.

### 一个重要陷阱：不要期望AI软件达到100%准确率——原因有三：一是机器学习技术本身仍有局限；二是训练数据不够；三是数据本身是脏的，可能标注错误（比如一个看起来完全没问题的绿色杯子被标成了次品）或模糊不清（比如杯子上有个小划痕，有人觉得算合格有人觉得要算次品）；这些问题有些可以改善——多收集数据、清理错误标注、让专家统一标注标准——但很多AI系统即使达不到100%准确率，依然非常有价值

> 结束这个视频之前，有一个陷阱我想劝你避开：不要期望你的 AI 软件达到 100% 准确率。说说为什么。假设这是你的测试集，我再加几个例子。以下是一些 AI 软件不可能做到 100% 准确的原因。第一，今天的机器学习技术虽然非常强大，但仍有局限，它们不是万能的——你可能恰好碰上一个对今天技术来说非常难的问题。第二，数据不够——如果你没有足够的数据，特别是没有足够的训练数据让 AI 软件来学习，那要拿到很高的准确率可能非常困难。第三，数据是脏的——数据有时候标注错误，比如有个绿色咖啡杯看起来完全没问题，但标签写着它是次品，这个错误标签会伤害 AI 软件的性能。数据还可能是模糊的——比如有个咖啡杯这里有一个很小的划痕，有人可能觉得算合格，但有人可能觉得应该算次品。甚至不同专家之间可能都不确定这个咖啡杯该不该通过质检。这些问题有些是可以改善的——比如数据不够可以尝试多收集数据，更多数据往往有帮助；也可以清理标注错误的数据，或者让工厂专家对模糊标注达成更好的共识。但很多 AI 系统即使达不到 100% 准确率，依然非常有价值。所以我劝你跟 AI 工程师讨论：什么水平的准确率是合理的？然后找到既能通过技术尽调又能通过业务尽调的目标——不一定需要 100% 准确率。
> Before wrapping up this video, one pitfall I want to urge you to avoid is expecting 100% accuracy from your AI software. Here's what I mean. Let's say this is your test set, which you've already seen on the last slide. But let me add a few more examples to this test set. Here are some of the reasons it may not be possible for a piece of AI software to be 100% accurate. First, machine learning technology today, despite being very powerful, still has limitations and they just can't do everything. And so you may be working on a problem that is just very difficult, even for today's machine learning technology. Second, insufficient data. If you don't have enough data, specifically if you don't have enough training data for the AI software to learn from, it may be very difficult to get a very high level of accuracy. Third, data is messy and sometimes data can be mislabeled. For example, this green coffee mug here looks perfectly okay to me. So the label of it being a defect looks like an incorrect label and that would hurt the performance of your AI software. And data can also be ambiguous. For example, it looks like this coffee mug has a small scratch over there and it's a pretty small scratch. So maybe we will think it is still okay, but maybe this should actually have been a defect. Or maybe even different experts won't agree if this particular coffee mug is okay and should pass the inspection step. Some of these problems can be ameliorated. For example, if you don't have enough data, maybe you can try to collect more data and more data will often help. Or you can also try to clean up mislabeled data or try to get your factory's experts to come to better agreement about these ambiguous labels. So there are ways to try to make these things better, but a lot of AI systems are incredibly valuable even without achieving 100% accuracy. So I would urge you to discuss with your AI engineers what is a reasonable level of accuracy to try to accomplish and then try to find something that passes both technical diligence as well as business diligence without necessarily needing 100% accuracy.
